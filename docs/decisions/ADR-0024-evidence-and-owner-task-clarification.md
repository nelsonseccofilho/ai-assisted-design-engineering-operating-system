# ADR-0024 — Clarify evidence authority, delivery and owner tasks

**Date:** 2026-10-15
**Status:** PROPOSED
**Scope:** additive shared contracts; no release or private adoption

## Context
Persisted adopter policies contain reusable safeguards as well as project-specific workflow choices. Evidence, permission, artifact verification and formal completion can be conflated. Multi-artifact work can accumulate competing status stores.

## Decision
Propose additive evidence/delivery, design-foundation QA and optional owner-task contracts plus unconfigured review seeds. Recover existing evidence, reconcile chronological authority, verify target-specific reads and authorized mutation readback, preserve one authoritative task owner and report verification independently of task acceptance. Apply the Master and project authority without changing bootstrap, task enums or populated data.

## Evidence and limits
Repository inspection confirms operational adoption and documented pilot limitations, not universal process effectiveness. The public promotion review preserves those distinctions. Original media and private design state were not reproduced. A source policy approval does not validate all of its execution.

## Alternatives
Copying populated records leaks private context. Making every adopter policy mandatory overstates maturity. Keeping all reusable lessons private prevents review. Additive contracts allow bounded review without those consequences.

## Compatibility and QA
Preserve 3.6.0 metadata, the eight-file bootstrap, canonical runtime root and read-only synchronization. Classify new shared/configured paths. Verify links, alias parity, existing regressions, maturity cases and sanitization. No private runtime or design artifact is changed.

## Supersession
None. Existing authority, ownership, compatibility and acceptance contracts prevail. This proposal is not acceptance or a released extension.
