# Eight-session retrieval comparison — 2026-10-15

**Protocol:** retrieval-comparison-v1.1, frozen input commit `72e557dc0c36f726e29691ad951697831423a870`.
**Scope:** METH-021 exploratory synthetic AI trial; architecture 3.6.0.
**Disposition:** context recovery and explicit index retrieval observed; **no read-volume saving demonstrated**. No general pilot promotion.

Eight fresh AI chats completed the prespecified balanced design. All sixteen case observations passed scoped source-recovery/critique review and instrumentation gates, with no source mutation. Every available index was explicitly retrieved. The index added one document read while the same eight case documents were still consulted: measured case-source volume increased by approximately **18.6%** across the equally represented cases.

See the [frozen protocol and kit](../examples/retrieval-comparison/README.md), [sanitized numeric results](../examples/retrieval-comparison/results-2026-10-15.json), and [staged plan](PILOT_VALIDATION_NEXT_CYCLE.md). Raw conversations, real task identifiers, machine paths and coordinator answer records are not published.

## Execution and provenance

The eight planned slots were fixed before dispatch: four spontaneous-choice sessions and four guided index-first sessions, each assessing two fictional cases. GARDEN/SKY order and INDEX/FLAT availability were counterbalanced within each regime. The eight rooms were frozen with source/tool hashes before any new chat began.

Each task was created as a fresh projectless conversation, without forking a parent conversation, passing this discussion or supplying the answer key. Only its assigned room and task instructions were supplied. Existing reviewer chats were not reused. Dispatch alternated the regimes after the first spontaneous session; sessions overlapped on the same host.

- Eight actual AI sessions, sixteen case observations, **zero human participants**.
- Each conversation had one task turn and a final assessment. Available command transcripts showed TASK.md and the metered reader; no outside-scope source access was observed. This is not an OS sandbox or a proof about hidden model training exposure.
- The task/history evidence supports fresh supplied context. Default Codex configuration was used; exact provider/model identity was not independently verified and remains null in the data. No cross-provider claim is supported.
- All eight attempts were retained; no failed/unfavorable attempt was replaced and no extra participant was added.
- Each room's ninety frozen source files matched after completion. Receipt files were separate from those sources; no source mutation was detected.

These are independent conversation contexts, not sixteen independent participants or sixteen distinct problems. The two cases repeat across the eight sessions.

## Quality and procedural assessment

The AI coordinator, who also prepared the fixtures, graded the answers against the frozen source key and authoritative case files. This was an **unblinded AI source-based assessment**, not human acceptance or a blinded independent grading panel.

All sixteen observations recovered the workstream/operator/status/artifact/next action, canonical component and accepted/proposed decision distinction. All kept annotations within the local artifact scope, identified the required unresolved criteria and distinguished a limited label refinement from enabling publication or permanent saved-data deletion. No answer claimed proven product write access, publication or functional acceptance.

Source pointers existed within the assigned room and appeared in reader receipts. Some answers annotated ACTIVE or the recorded next action with review commentary; those fields were interpreted against the source without rewriting the raw answer. This supports scoped recovery, not strict structured-field interchange or runtime-state import.

Mandatory manifest/bootstrap preceded case reads; case order and completion markers matched the plan. All four guided INDEX observations retrieved the full index before case-document access. No procedural error was detected by the frozen v1.1 summary. Its `balanced_design_complete=true` means all sixteen planned observations met the local eligibility gates; it does not establish general methodological efficacy.

## Case-source measurements

Each table cell has two eligible observations. Values were identical within each case/availability cell.

| Regime | Case | FLAT bytes | INDEX bytes | Added bytes | Relative increase |
|---|---|---:|---:|---:|---:|
| Spontaneous | GARDEN | 3,593 | 4,265 | 672 | 18.70% |
| Spontaneous | SKY | 3,649 | 4,322 | 673 | 18.44% |
| Guided | GARDEN | 3,593 | 4,265 | 672 | 18.70% |
| Guided | SKY | 3,649 | 4,322 | 673 | 18.44% |

Explicit index retrieval occurred in **4/4 available-index spontaneous observations** and **4/4 available-index guided observations**. In both regimes the INDEX condition had thirteen unique paths and twelve reader operations per case, versus twelve paths and eleven operations in FLAT. All participants still read case documents 01–08, so no source-document retrieval was avoided.

The equally weighted case comparison is 8,587 INDEX bytes versus 7,242 FLAT bytes, an extra 1,345 bytes (**18.57%**). Across all sixteen observations, case-source payload totaled 63,316 bytes. These descriptive differences apply to these fixtures and instructions; they are not a causal productivity estimate or a general rule that indexes increase cost.

Unlike the [earlier two-session trial](PILOT_VALIDATION_2026-10-15.md), this trial observed actual index retrieval. The absence of read-volume benefit therefore cannot be explained solely by non-use of the index.

## Bootstrap and time boundaries

All eight sessions encountered initial output truncation and recovered the full mandatory bootstrap through repeated reader calls. The source bytes of a complete bootstrap were 41,933 per invocation. The sessions recorded twenty total bootstrap invocations (two to four per session), plus one manifest read each.

Common manifest/bootstrap source payload totaled **864,188 bytes**, reported once per session and separately from the 63,316 case-source bytes. Repeated reads were retained; no bootstrap file was omitted to reduce the count. TASK.md, internal reader/Git metadata, setup and grading operations are outside these instrumented payload counters.

Per-case first-operation-to-completion intervals are retained in the numeric results. They exclude final answer composition, and the concurrent sessions shared host/tool latency. They do not establish faster work, cognitive effort, token use, billing or financial savings. Provider/model and total token consumption were not measured.

## Finding and disposition

**METH-021 remains OPTIONAL_PILOT / PILOT_PENDING.** The narrow recovery and index-use behaviors were observed, but this fixture does not support an efficiency promotion. Keep the index optional and do not add a mandatory index-first rule to the operating framework based on this result.

Stop the efficiency-promotion attempt for this fixture. Retain the zero-benefit result. A later trial requires a justified new gap and a new prespecified protocol before execution, rather than repeating sessions or changing criteria after inspecting these outcomes. Output-recovery overhead is a distinct tooling question; any remedy must preserve every mandatory bootstrap file and must be evaluated separately.

The additional source-recovery/critique observations do not complete human handoff validation, native-editor annotations/reflow, functional backend/permission testing, comparative delivery efficiency or external-method adoption. No catalog value, ADR status, runtime pin, compatibility contract or released framework version is changed by this report.
