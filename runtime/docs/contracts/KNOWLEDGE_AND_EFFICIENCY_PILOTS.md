# Shared knowledge, comment triage and efficiency pilots

**Ownership:** SHARED_CONTRACT. **Maturity:** OPTIONAL PILOTS; independent interoperability and cost/productivity benefits require measurement.

## Recover selectively after mandatory bootstrap
Keep every file required by the current manifest. Then use indexes, IDs, current state and handoffs to load relevant details on demand. Concise summaries point to canonical records; do not create a parallel memory service, duplicate status store or endless research pipeline by default.

Link existing decisions with related, compatible, conflicts_with, depends_on and supersedes only when the evidence supports that relation. A later proposal cannot supersede an accepted rule solely by being newer. Cross-artifact knowledge can be read across owners without moving their task or mutation authority.

## Comments are evidence, not automatic tasks
Preserve private thread/parent identity, attribution evidence, timestamps, resolution state and artifact location. Shared-account authorship needs corroboration. Distinguish reminder, question, hypothesis, decision and defect; reconcile with source chronology and actual artifact state.

Triage already addressed, duplicate, superseded, new systemic cause and unvalidated proposal. One source-level repair may address several symptoms; check consumer impact before multiplying tasks. Use the [comment triage seed](../templates/COMMENT_TRIAGE.md) in existing records. A resolved thread neither proves implementation nor grants acceptance.

## Research and cost
Record a reference's exact source/date, claimed contribution, evidence limits, license, current-method overlap, dependencies, privacy/security risk and a small testable gap. A source's recommendation is not a project decision. Inspect applicable license and provenance before reusing third-party text/code; this package does not install or adopt external systems.

Consider time, usage limits, maintenance, reprocessing and data exposure, not only API prices. Prefer existing adequate capabilities; do not require a particular provider, paid API, multi-agent system or new subscription. Measure a baseline and actual delivered units before claiming savings.

Test with independent operators/sessions recovering the same scoped rule and limits. Record time/reads, discrepancies, duplicates avoided, unauthorized changes and delivered outcomes. Stop or defer if no real gap or measured benefit exists. Pilot approval and documentation persistence are not efficacy validation.
