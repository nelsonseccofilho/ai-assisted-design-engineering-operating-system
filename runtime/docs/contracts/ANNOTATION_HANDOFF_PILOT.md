# Contextual annotation and independent handoff pilot

**Ownership:** SHARED_CONTRACT. **Maturity:** OPTIONAL PILOT. Documented cases report narrow contextual recovery; broader usability, functional completeness and post-update persistence need separate evidence.

## One information item, one responsible location
Keep shared behavior with its canonical component/contract, operational history with its owner, and concise contextual guidance near the relevant artifact. Avoid repeating whole specifications, logs, timestamps, node inventories and handoffs on every instance.

Choose an existing annotation-capable anchor appropriate to the actual tool; inspect current capabilities rather than assuming every node supports annotations. State the scope of a group note explicitly. Keep exceptional node-specific behavior local and discoverable.

Map annotation categories from the current file/session. Category names/IDs are not cross-file constants, approvals or implementation permissions. Distinguish a local note, a group note and an inherited component note by ancestry and scope. Do not apply inherited business content to an unrelated scene.

Before authorized removal or consolidation, preserve an exact private snapshot of original content, category, ancestry and relevant properties. Retain the historical report and explicit supersession. Check both owner history and changed artifact readback; annotation count/content alone does not prove visual usability.

## Test the handoff independently
Give a fresh reviewer the declared starting artifact and normal authorized access, without supplying the answer as part of the test. Ask them to recover context, component source, governing decisions, assumptions, permission limits, missing functional requirements and next safe action.

Record the actual starting conditions, consulted sources, exact output, attribution, assessment criteria and limits. Separate:
- contextual retrieval;
- conditional visual implementation planning;
- functional specification completeness;
- human usability/legibility;
- actual runtime and accessibility behavior.

One independent case is one case. Prior internal retrieval repetitions and duplicated reports are not additional independent tests. An attributed external report is not a newly rerun experiment.

Recheck local/inherited notes after component synchronization. A structural property or hyperlink target does not prove click navigation or expanded-native-note visibility. Promote only after representative repetitions and explicit governance review.
