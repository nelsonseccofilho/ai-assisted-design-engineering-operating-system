# Evidence reconciliation and journey coverage

**Ownership:** SHARED_CONTRACT. **Maturity:** generalized procedure proposed from adopted policies and documented cases; historical outcomes are not newly reproduced tests. Existing authority and privacy rules control its use.

## Source inventory before interpretation
Record source identity, revision/hash when available, author attribution, capture time, context window and present accessibility. Distinguish an original recording, machine transcript, edited extract, archive copy and a derived analysis. Duplicate exports, overlapping transcripts and repackaged archives are not independent confirmations. Keep private locators and original excerpts in the private evidence index.

For a scoped question, reuse prior reconciled analysis with its limitations; revisit primary material only for a specific uncertainty, contradiction or changed scope. A filename, label search or missing search result does not prove absence. Marketing pages and historical reference screens establish only what they actually show, not product authority.

## Reconcile the decision chain
1. Identify the subject, audience, problem and exact context surrounding the statement.
2. Classify exploration, question, request, decision, observed implementation and explicit acceptance separately.
3. Build origin → refinement → contradiction → supersession/current decision links. Later date alone does not establish supersession.
4. Preserve modal force and exceptions: may is not must; conditional is not universal. A narrow exception does not grant a broader capability.
5. Resolve pointing/deictic statements against the corresponding visual source. If unavailable, preserve the uncertainty; do not invent geometry, actors or referents.
6. Compare the current owning artifact and version. A new source may reveal an already delivered solution, a real gap, or obsolete work.
7. Record the remaining question and accountable authority; continue independent authorized work.

Do not count several documents derived from one meeting as several independent approvals. A machine-readable transcript being structurally valid does not establish speaker identity, context completeness or a correct requirement.

## Map topology before tasks
Distinguish organization → product/application → functional domain/owning artifact → journey → scenario/state → screen/component. Work packages and source requirements link to that topology; they are not interchangeable levels.

Inventory relevant entrances, outcomes, actor contexts, states, versions, connectors and cross-artifact dependencies. Link each requirement to its current scenarios and acceptance evidence. A single frame, one screenshot, historical satisfied label or FINAL name does not establish complete journey coverage.

Create only evidence-backed owner tasks for actual gaps. Preserve source origin separately from execution ownership, route ambiguity to a review queue, and maintain the existing authoritative task ledger. Use the [reconciliation seed](../templates/EVIDENCE_RECONCILIATION.md) where the owner record lacks this structure.
